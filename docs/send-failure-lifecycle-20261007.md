# Failed sends and immediate local Stop

The laptop displayed `T3 connection closed` during response registration. A historical lease was 1,676,065 bytes; T3's file RPC returned only its first 1 MiB. The device rejected the incomplete file, then closed the socket shared with a new registration. Concurrent interactive work received the close error. The failed message IDs inspected in T3 were absent, while adjacent successful sends completed. This explains the intermittent behavior.

A file read or RPC failure now leaves a healthy shared transport open. Only an actually closed transport is replaced. Discovery also skips completed historical responses that have no response boundaries left in the note. Incomplete file data is still rejected and never parsed as a valid lease. No historical response or journal is deleted to work around the transport limit.

The first release, 2.34.35, omitted the transport status getter from the production host-files wrapper. Its connection-isolation fixture exposed that getter directly and missed the wrapper defect. The follow-up preserves the getter through the real wrapper and requires affirmative evidence of a closed transport before replacing it. Tests exercise both a provider with that status and one without it. A post-update laptop failure was accepted by T3 before terminal cleanup; its host lease records `accepted: true`, `discardResponse: true`, and completed interrupted cleanup. This is an acknowledgement failure, not proof that T3 rejected the prompt.

A send retains its exact identity while it is in progress, then releases its local request on success or failure. There is no Retry/Discard queue or retry method. A failed send removes its newly reserved display immediately, records a failure, and starts independent host cleanup. Startup closes old unresolved sends rather than resending them. Failed agent command IDs retain a compact terminal receipt and refuse a second dispatch. Successful command receipts remain idempotent.

Host cleanup writes a stop intent before asking for an acknowledgement. The intent carries `discardResponse` for a failed new response. Registration checks for an earlier intent, so a late registration cannot recreate an active response. The host saves an empty final body for that failed display and interrupts only a turn bound to its exact message. Failed steering/continuation closes the attached display while retaining already received text. Cleanup never dispatches another prompt. A remote acceptance cannot be undone atomically when an acknowledgement is lost; the log reports that uncertainty.

Stop seals the native projection synchronously before remote work. Ordinary received text remains visible; active controls and Working indicators disappear. Device-local stop records survive reload and block late direct events and stale host records. Explorer activity is suppressed immediately. Other devices also seal a native display when they receive the host stop intent. Saved projection anchors remain internal until the host's checked final commit removes them. Native save, conflict handling, selections and ordinary undo continue to use the existing projection and commit-proof rules.

The stop intent also carries the frozen body visible on the stopping device. The host uses that body for its final checked commit rather than replacing a newer direct-stream paragraph with an older host snapshot. The first captured body is durable and repeated Stop commands cannot overwrite it. Failed new responses still commit an empty body.

The failure log stores at most 64 records per device and vault. Records contain stage, elapsed time, identity fields, delivery state, a redacted error stack, RPC error kind and bounded nested cause. It excludes prompts, attachments, sessions and credentials. Open **Send failure log** in settings, or use **Export send failure log** to copy JSON. General event/stream logging remains disabled.

Regression tests cover a truncated 1.68 MB read concurrent with real protocol registration, replacement of a dead transport, a failure intent before late registration, explorer cleanup before acknowledgement, native Stop with rejected or hung remote cleanup, multiple native panes, late stream and host events, reload, redaction and log retention. Mobile bundle tests prove terminal request behavior only; they do not establish native phone behavior. Live QLO2 evidence belongs in the immutable release receipt.
